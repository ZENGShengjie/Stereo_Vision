# 540p 降级消融实验总结

两种独立的 "540p" 概念必须区分清楚：

| 概念 | 配置项 | 影响的模块 | 默认值 |
|------|--------|------------|--------|
| USB 摄像头采集分辨率 | `STEREO_USB_HEIGHT` | 摄像头 `read()` 耗时 | 1080 |
| SGBM 内部计算分辨率 | `SGBM_WIDTH/HEIGHT` | SGBM 深度计算 | 320×240 |

---

## 实验对比：540p vs 1080p

### 摄像头采集层

| 模式 | 摄像头 read() 耗时 | FPS |
|------|-------------------|-----|
| 1080p | ~1000ms | ~1 |
| 540p | ~180ms | ~5-8 |

某些廉价 USB 摄像头在 1080 模式下数据传输太慢。540p 高度只有 1080 的一半，数据量减半，摄像头切到快读模式。

### 自动降级逻辑

启动时探测摄像头 `read()` 耗时：
- ≤ 300ms → 保持 1080p
- \> 300ms → 自动降级到 540p，重新打开摄像头，FPS 提升到 ~5

阈值 300ms 是经验值：在这个阈值以下 FPS 可达 5+；超过这个阈值 FPS 会急剧下降到 1。

### 图像尺寸处理链

```
摄像头输出 raw frame
        │
        ↓
  _resize_if_needed()  ← 仅当双设备模式且尺寸不匹配时才 resize
        │
        ↓
  高度对齐到 MONO_HEIGHT (1080)  ← 始终 resize 到 1080 高！
        │
        ↓
  _apply_rectify() 极线校正
        │
        ↓
  输出 (1080, 1920, 3) × 2  ← 无论输入是 540 还是 1080，输出固定 1080
```

### SGBM 层

```
输入给 SGBM 的图像尺寸: 1920 × 1080 (固定)
        │
        ↓
  缩放到 SGBM_WIDTH × SGBM_HEIGHT = 320 × 240
        │
        ↓
  SGBM 计算视差
        │
        ↓
  视差值放大回 1920 空间
```

**结论：540p vs 1080p 对 SGBM 视差数值完全无影响。**

SGBM 的输入分辨率始终是 1920×1080（因为 `read_rectified_pair` 里做了高度对齐）。540p 只是改变了摄像头 raw 采集的分辨率，但经过对齐后，进入 SGBM 的图像尺寸完全一样。

---

## 各模块影响汇总

| 模块 | 540p 效果 | 1080p 效果 |
|------|-----------|------------|
| 摄像头 read() 速度 | 180ms, FPS5 | 1000ms, FPS1 |
| 高度对齐 resize | 960×540 → 1920×1080 (2× 放大) | 原生 1920×1080 (无缩放) |
| SGBM 视差数值 | **完全相同** | **完全相同** |
| YOLO 检测框 | **完全相同** | **完全相同** |
| 右框映射 | **完全相同** | **完全相同** |
| 画面细腻度 | 有损失（540→1080 放大） | 完美原生 |

---

## 关键发现

1. **540p 的唯一收益是 FPS**：从 1fps 提升到 5fps，用户体验从"幻灯片"变成"可用"
2. **540p 的代价是画质**：摄像头 raw 是 960×540，经过 2× 放大到 1920×1080 后，画面会比原生 1080p 模糊一些
3. **540p 不影响深度计算**：`read_rectified_pair` 里有硬性高度对齐，无论摄像头原始输出什么分辨率，进入 SGBM 的图像都是 1920×1080
4. **自动降级阈值 300ms 是经验值**：在这个阈值以下 FPS 可达 5+；超过阈值 FPS 急剧下降到 1

## 如何启用 540p 模式

```powershell
$env:STEREO_USB_HEIGHT = 540
python main.py
```

或通过环境变量持久化到启动脚本。
